# 操作与恢复

## 通过 MCP 读取和微调

1. 连接 `qqspeed-editor` 后调用 `editor_status`。它通过 Windows 查询窗口、前台、权限和可访问性树。2026-11-23 本机构建区窗口的 UI Automation 原始树只读到标题栏子项。精准编辑字段由本地面板识别提供，结构化响应可直接用于比较数值。编辑器在后台时可按窗口句柄用 Windows Graphics Capture 读取画面；后台读取只用于观察。
2. `read_editor` 返回面板类型、组件类型及具名数值。已验证的面板包含位置、旋转、缩放、尺寸各三个轴。可用 `activate=true` 切到编辑器。窗口失焦、被遮挡或游戏权限较高时，依据返回的 `write_blocker` 排查。同类型组件的橙色轮廓只用于检测选中画面变化，模型没有提供场景对象 ID。
3. 在已获准的操作范围内，使用 `nudge_field` 微调位置或旋转。传入最新的 `observation`、字段名、读到的原值与单击一步应得的新值。步长依据该游戏面板的实测。工具只点一次加或减；每次调用消耗凭据。缩放和尺寸当前只读。
4. 只有 `verified` 可登记为已完成。工具检查目标轴达到预期，其余 11 项仍与操作前相符。`blocked` 代表未发起点击。`uncertain` 代表可能已发生更改，先重读并核对实际对象和数值，禁止自动补点或接着预输入下一行。

## 建筑的选取、定位与复制

在当前客户端安装目录下只读检查 `Userdata/AuroraShortcuts.ini` 与 `Userdata/aurorasetting.json` 的 `Shortcuts`、`Settings`。按键可自定义，两个文件列出的动作也可能不同。先确认当前窗口与输入焦点，只有视口得到焦点时才发送建模快捷键。

2026-11-23 本机配置记录：`T` 多选，`G` 成组，`Ctrl+Shift+G` 解组，`F` 聚焦选中物体。`1/2/3/4` 分别切换移动、旋转、缩放、镜像工具。小键盘 `4/6`、`2/8`、`3/9` 分别对应 X、Y、Z 负向/正向移动。`F9` 切换自由相机见 INI。`Ctrl+C` 切换复制模式已有单件实测，其余列出的绑定本次仅核对配置。

制作重复开间时，先精确输入一组墙柱的位置与尺寸，再测试多选成组、复制整组和按开间距定位。在获准的样间上对照复制前后的占用、两根柱子的间距和门洞净宽，确认内件跟随、原件留在原位。测一次轴向按键前后的坐标差，再决定用按键移动还是直接输入绝对坐标。网格大小、网格吸附、贴地和道路吸附分别检查；网格大小本身不能证明每次按键的步长。切换相机后重新识别视角与坐标轴。复用组首先节省操作次数，占用仍按实测增量计算。

## 截图通道和输入权限

- 窗口捕获超时且按该接口约定重试仍失败时，可用当前用户与工具允许的窗口捕获或桌面局部截图；已允许切换截图方式时直接切换。仅保留目标客户区，避开其他应用、账号和聊天信息。使用专用桌面工具时，按该工具的操作说明获取窗口与截图。后台读取优先试 Windows Graphics Capture，最小化或捕获源无效应返回当前限制。
- 截图和输入分开诊断。备用截图成功后，重新识别编辑器位置、窗口边界、遮挡、缩放和当前选中对象；坐标需按新画面重新计算，不沿用历史坐标。输入仍使用当前获准的接口。
- 备用方式也不可用时，准确报告尝试过的方式和错误，再请求必要的用户协助。未取得可验证画面前不盲操作；不得把旧截图当作当前场景。

## 2026-11-14恢复与校验补充

- 窗口截图接口曾持续报 `window capture timed out`，当时用桌面截图成功。切换通道后重新核对位置、遮挡和清晰度，再按该次授权继续。
- 原受限输入辅助程序有停止记录，已不响应；旧ready文件不能证明程序仍在运行。恢复同范围连接后先验证状态、窗口边界和实际截图。不要把备用程序、提升权限或固定坐标设为技能默认步骤。
- 本次鼠标移动后等待约0.15–0.20秒再点击，减少了点击落在旧位置的问题；按现场响应验证，不解释成已证明的引擎机制。
- OCR曾把预算旁图标读成额外数字9，也把负号读成“–”。仅裁切数值区域并统一负号；不盲删首位数字。预算异常先看画面，辨别副本是否已创建。
- 同类型复制可跳过已验证且不变的颜色、旋转、厚度字段，但仍读回完整变换。位置始终重新设置，避免拖拽偏移。失焦时停止，恢复后补齐pending对象而非重建。

## 历史实测（2026-11-12）

- 复制模式下拖动选中对象的坐标轴可以产生副本；Ctrl+C曾切换复制模式，不能当作普通剪贴板复制粘贴。
- 选择不同对象时曾自动切回属性面板；点击已选对象可能取消选择并关闭面板。
- 自动保存期间，点击可能没有生效；窗口失焦时输入必须停止。
- 保存按钮触发“作品上传中”，随后“作品上传成功”。仅看上传提示消失不能充分证明成功。
- 当时通过立方体颜色、位置和尺寸字段构建了分层Logo。历史屏幕坐标不能复用，窗口已在后续日期移动。

## 批量执行阶段

为每个组件记录计划类型、变换、颜色、执行阶段和最近验证证据。阶段至少包含：准备创建、已创建、已配置、已核对。创建后先确认新增对象及组件类型；配置后读回参数并检查画面。无法读回时缩小批量并增加视觉观察，不把标题图像匹配当作完整验证。

恢复时根据实际选择、预算计数变化、组件位置和记录判断当前阶段。已创建但未完成配置时修复当前对象，不再复制。无法确定时停止该批次，先定位对象。不能因脚本重跑而累积重复几何。

所有操作需要当前截图或可访问性状态支持；新增对话框、视角变化、窗口尺寸变化使旧坐标失效。

### 原生组合拖放和选错恢复

拖前记录卡片名、地图基线、当前空位与视角。客户端坐标与整桌面坐标应按当前捕获源换算。每次只从可识别的卡拖一个实例。拖完先看占用差、橙色轮廓与组面板。一次多卡拖放可以用每次读数串成表；无需每一帧全屏发给用户。组合面板常见位置、旋转、缩放三个区，共九个值；普通几何精准面板通常还有尺寸，共十二个值。随包 OCR 只对已识别的完整十二字段面板提供微调。九字段、卡片列表、占用值均可用当前裁图核对，不补造结构化读数。

精确定位先对选中组的名字或类型、占用量、位置、选择框范围。发生过误选平台后改动坐标的情况：先停输入，仅恢复此次确定写错的轴，逐轴读回原值；重新选组后比对组占用，再改一个字段并读回。组标题“组件”或一次拖放的光标轨迹均不足以证明选中正确。失焦、层级较高、读数矛盾或未确认选中时，不顺手撤销用户的其他操作。带单次消费和窗口检查的本地拖放工具见 [一次拖放](setup.md#一次拖放)。

2026-11-14补充：从列表拖拽到场景可创建上述四种样件；只点击列表后点场景未创建文本。修改字段后按Enter并读回。斜坡旋转Y输入90曾显示89.96，应按目标接缝需要判断误差，不能循环盲输。字体开启竖排后，新增字距行导致下面字段位置移动，必须重新定位。
