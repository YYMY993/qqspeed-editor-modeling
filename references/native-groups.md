# 本地原生组合

2026-11-23 在已打开的构建区实测过运行中刷新本地卡片。静态组合可在后台生成。实际放入地图、改整组坐标和保存依赖能接收输入的编辑器。其他安装先以自己的原生样本和库面板核对兼容性。

## 离线制卡与重读渲染

从技能自带的 [八件木门廊草案](../assets/gate.plan.json) 起步，命令见 [安装与自检](setup.md)。`scripts/native_card.py` 会直接生成独立根组的 v1/v5 JSON。它随带五种静态样本，分别是立方体、球体、圆柱、等腰三棱柱和原生 Text。环境件、箭头等从当地编辑器把所需资产做成一个自用组合，用 `--from-card <样本的component.json>` 加入已验证的模板。可多次传入，按顺序取第一个匹配的样本，再查随包基础件。同一资源有多种材质、姿态或碰撞时，选择与目标一致的单独样本。主动、静态、单一网格或文字的样本才能直接克隆；专有行为或多组件结构须另查原生导出，或直接在编辑器内摆放。

| 草案字段 | 含义 |
|---|---|
| `name`、`parts` | 卡片名称和独立构件数组。新版使用独立名称，路径可由操作者指定。 |
| 每件的 `name`、`template`、`position`、`scale` | 构件名、已核实的模板、相对组原点的 XYZ、原生网格缩放。填写面板的“尺寸”前先按单位缩放样件的实测尺寸换算。 |
| `rotation`、`color`、`collision` | 单位四元数 WXYZ，默认单位旋转。可用六位 RGB 设置已验证的色调。基础件可以显式指定碰撞，其他资产保留样本碰撞与网格属性。 |
| Text 的 `text`、`font_size`、`vertical`、`vertical_spacing` | 字符串、字号、竖排与竖排间距。游戏原生文字和实体颜色的存储色域不同，生成器单独换算。 |
| `budget` | 可选。用 `limit`、`unit_estimates` 和可选 `reserve` 指定本组预算。缺单价、估算超限会在写出文件前停止。实测仍以目标地图为准。 |

对同一草案和样本重复运行会产生相同的整数 ID 和文件内容。使用新目录保存版本；生成器拒绝覆盖不同内容。对新导出的文件运行 `native_preview.py`，用 `--view front`、`angle` 或 `back` 切换观察方向。渲染器重读实际配色、位置、四元数和原生缩放，并进行深度遮挡。立方体与三棱柱用基本几何，球、圆柱使用近似网格，原生 Text 需用 `--font` 指定当地有相应字形的字体，排版按样本字号近似。静态渲染支持单位变换的嵌套组。专有环境网格、原生箭头、不支持的组变换或材质效果用游戏实拍验证。遇到缺少的网格会明确停止，封面也可用本次已获准的实摆裁图。

## 生成和载入

1. 在当前客户端的 `Saved/ComponentLibrary` 下查找用户自己的组合。用「我的组件」中多个卡片名称与本地 `meta.json` 比对，确认当前账号目录。取同版本原生样例核对模板、网格资源、碰撞和文本属性。
2. 本次实测外层为 `AuroraComponentLibraryEntry` v1，内层 `component` 和 `spawn` 均为 v5。两棵列表以同一个整数 `$uid` 对应物件。保留 64 位整数精度，给物件及内部组件分配互不冲突的 ID，核对 `RootComponent.$ref`，组的 `Children` 最终只归属一个根组。物件 `Transform` 和对应 SceneRoot 的 `LocalTransform` 保持一致。四元数依次为 W、X、Y、Z。分栋子组保持单位变换时，叶节点可直接使用整街相对坐标。实测使用立方体、等腰三棱柱、球体和文本。
3. 用本 skill 的 `scripts/local_group.py component.json --cover cover.png` 预检。在确认的账号目录安装本次新建的组合时，追加 `--install-to "<账号目录>" --name "<卡片名>"`。脚本为新卡片分配独立目录，同内容同名时返回已有条目。准备的文件为 `component.json`、256×256 的 PNG 封面、含整数 `ModuleID` 和 `ModuleName` 的 `meta.json`。
4. 在「我的组件」核对卡片名称、封面与当前地图占用后拖入。选「编辑 → 精准编辑」，核对组的占用，再逐轴输入目标世界坐标并读回。实测组面板有坐标、旋转和缩放三段，普通立方体另有尺寸段。在地图里用两处接缝确认组原点和样件原点吻合。需要返工时，先记录已放置组的占用、位置和选中范围，用这些信息识别本次实例。
5. 本次若含外观验收，切到街口、主立面和反面检查。横匾按游戏里的成字宽度调整字号。本次七字横匾使用字号 48，字号 96 的首版溢出了底板。退出选中状态后拍实景。获准保存时观察「作品上传成功」；只拖放时到确认新增实例为止。

查库时从当前客户端可执行文件、WeGame 显示的安装目录或已知的 Saved 目录开始。在本机调用下面的只读工具，给出“我的组件”里能认出的实际卡名，可重复传入 `--card` 消除多账号重名。不传卡名仅列候选。空库可在已获准的情况下先从游戏生成一张独特命名的自用样卡，再定位对应账号。路径和账号查询结果留在本机。

```powershell
& $py -X utf8 (Join-Path $skillDir 'scripts/library_lookup.py') $gamePath --card $visibleCardName
```

只安装时，在自己的工作区生成组件和封面后运行下面的命令。`$accountDir` 须由现场卡片和目录比对确认，不按最后修改时间猜账号。`$cardDir` 是本次新卡的工作目录。

```powershell
& $py -X utf8 (Join-Path $skillDir 'scripts/local_group.py') (Join-Path $cardDir 'component.json') --cover (Join-Path $cardDir 'cover.png') --install-to $accountDir --name '本次新卡名称'
```

卡库热刷新可通过切到其他分类再返回“我的组件”验证。未见卡先复核账号、名称、安装层级与版本，避免重复上架。地图中已有旧版时，把新增和替换分开记录。替换前识别原实例和坐标，保留原件或已授权的恢复路径。

## 万事屋街区实测

七栋街区共 433 个构件。15 件手搭样间增加占用 300，418 件续建组合显示 4,285，地图增加 4,585。另将完整的 433 件组合单独拖入，实际增加 4,545，随后移除了验证用副本。估算其他场景时区分单件与原生组合，并以目标编辑器的前后读数校正。

样间楼梯净宽 1.72，踏步宽 1.68，六级逐级升高 0.20。双坡屋面的旋转分别为 +25.35° 和 −25.35°。屋顶瓦纹采用搭接细条，招牌采用原生文本。此轮验收覆盖外观、摆放和保存，车辆碰撞需另行试跑。
