# 造型、预算和可用证据

## 把参考变成真实构件

先选玩家能认出的三五处特征。多视图使用同一比例与地面原点。正面优先对外轮廓与招牌，斜侧对檐口出挑、窗洞和层次，背面只补参考图或行车路线看得到的结构。推定的进深、背面、道具遮挡应在评审图注明。对原图画遮罩、取色、描轮廓均可在离线阶段使用，交付组合内只能出现编辑器支持的真实对象与属性。

| 对象 | 优先保留 | 减件与检查 |
|---|---|---|
| 商街、木廊、旅馆 | 开间节奏、层高、屋脊、门洞、转角和店头字号 | 整面墙、长梁和檐板各用一件可缩放主体。门洞两侧和过梁围出净空；侧墙按实际墙厚收短。优化重复椽尾、后窗格、榫钉与背面装饰。门楣、凹口、楼板和碰撞件用变换清单逐件对照。斜屋面由半跨、起脊高度算坡角和斜长。 |
| 雪坡、覆雪石、树、雪岸 | 雪线、坡脚、树冠剪影、远近层次 | 用环境成品承担材质和大轮廓。第二块只补轮廓缺口或转折。拉伸前后看重复纹理、悬空及接缝。可滑性须在获准的测试里实跑。 |
| 反光建筑 | 玩家指定的固定银带位置、亮暗交界和宽度 | 让少量长银灰面与暗邻面直接构成固定高光。用同机位看“是否像参考中的反光”；只按已实现的固定外观交付，动态反射需要另有证据。 |
| 招牌、转向箭头 | 远处识别、字宽、面朝赛道、左右朝向 | 一行字优先一个原生 Text。竖排、间距、字号和三轴缩放分别对版。缺字时先核对游戏字形，只补缺失的标识笔画。原生箭头从实际卡片取样，以局部原点定位，防止反向或被底板吞掉。 |
| 踏板车和头盔 | 车轮与轮毂同轴、车架负空间、头盔壳口、风镜和束带 | 用圆柱、球壳或半球承担曲面，局部用宽条、弧段。头盔实摆曾发现半球倒扣，该款沿 X 翻转 180° 修正，从底面确认开口。先合并细环和过密的杆件。 |
| 二维人物、徽记 | 发型外轮廓、脸与眼、衣服色块、手与道具的相对位置 | 先画轮廓和少数主色面，用薄块、三棱柱、弧形拟合。相同颜色、同面且不会吞掉空隙的区域合并，发梢与衣褶局部再细分。留层间距离防止闪烁。原生文件应能枚举出每片几何。交付正面与斜侧，标清侧厚、像素阶梯和估算成本。 |

人像透明 PNG 只可用于比对轮廓或制作封面。一轮按高 138 个采样格、14 色、同色矩形合并的六个人物仍分别用了 1,472、773、1,156、2,274、1,816、2,399 件，合计 9,890 件。按每件 10 估算约 98,900 占用，该例没有地图实测值。做高还原人物时先拿一个头身比例和服装最复杂的样件试算。超预算就减色、扩大轮廓块或简化次要细节，展示可落地的取舍后再扩成整批。

如需快速比较纯构件二维人物方案，随包的 `scripts/mask_plan.py` 可把透明背景的人物轮廓转成实体草案。每个色面尝试横向和纵向合并，选件数较少的一种。运行下例后把草案交给 `native_card.py`，再从成品导出正面和斜侧。输入图不会写进模型。薄矩形仍有阶梯感，面部和手部需要时可在草案中换用经验证的斜片或弧段。下例高度、色数和单价只用于试算，按本次目标调整。

```powershell
& $py -X utf8 (Join-Path $skillDir 'scripts/mask_plan.py') $subjectPng --name '人物甲·样稿' --height 64 --colors 8 --world-height 3 --thickness 0.08 --unit-estimate 10 --budget 10000 --output (Join-Path $demoDir 'person.plan.json')
```

## 怎样报“占用”

1. 记录对象、版本、碰撞状态、单件或组合、地图基线。估算写成各类件数 × 对应实测或暂估单价，另留余量。未知单价单列。配置权重、件数、文件体积、场景占用分别处理。
2. 用户说“一组 1 万”就逐组验；说“整批 2 万”就验整批。以当次最新范围为准。重做保留已认可的建筑、人物姿态或主要造型，只优化用户点出的部分。
3. 同一张地图一次放一组并读回。实际增量 = 放后总占用 − 放前总占用。用选中组面板、标题/轮廓/位置交叉核对。地图发生自动保存、其他人编辑、编辑模式切换或基线跳变时，把差异标为待核，先不归到当前组。上限是硬要求时，没有实测就明确“估算符合，实测待核”。
4. 新版本另建卡片。以同机位对比两版并保留碰撞件和文字清单。用户只委托拖放时，交接这次实例和最小读回；重开、试跑和发布由实际授权决定。

## 明确图像来源

给每张预览注明原图、概念图、草案示意、成品文件离线渲染或实拍。成品离线图应读取本次交付的 `component.json`，可记录 SHA-256 前缀、件数和镜头。原生字体用本地字体近似时标注排版差异；引擎专有网格、贴地、光照、阴影、碰撞或介面状态应在游戏里确认。效果稿里有精细人物、实际组件里只有几块色板的版本应退回重建。
